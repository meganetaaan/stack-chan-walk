# Robot board review

図が整っていること、ERC/DRCが通ること、実機として成立することを分けて判定する。
これはレビューのSkillであり、基板の自動生成・自動修正・製造承認のSkillではない。

## 1. レビュー対象と証拠を固定する

1. 対象ブランチ/コミットと差分を確認する。PRではbase/headを記録し、変更の影響を
   受ける電源・帰路・接続先まで追う。行数差分だけで判断しない。
2. `schematics/`、`board/pcb/`、`board/mechanical/`、`validation/`と関連する
   設計資料を確認する。回路図の階層ルート、全子シート、PCB、プロジェクト設定、
   カスタムルール、BOM、接続表、機構CAD、製造出力の対応を特定する。
   #29（回路図/BOM）、#30（配線解析）、#31（機構/製造）の受入条件も参照する。
   図面名、電圧、サーボ数、電流値を過去の記述から固定しない。
3. CADの種類/バージョン、基板版、製造先/積層/銅箔厚/製造制約、負荷条件を記録する。
   値がない場合は推定値で合格にせず「未確認」とする。
4. [チェックリスト](references/checklist.md)を読む。判断根拠が必要な場合は
   [出典と適用範囲](references/sources.md)から原文/採用部品のデータシートを確認する。
   RTブログの実例、プロジェクトへの適用判断、依頼者の追加要求を混同しない。

図面がまだない、画像しかない、ライブラリ/子シートが欠ける場合は、その不足を明示し、
確認できる範囲だけレビューする。図面未追加を設計不良と断定せず、合格にも数えない。

## 2. 自動チェックを先に実行する

KiCadの場合は、下記のローカルlintを使う。Python 3.10以降と`kicad-cli`が必要。
入力は実在する階層ルート回路図/PCBを明示する。子シートの再帰globによる単独ERCや、
READMEしかないディレクトリに対する空振り成功を避ける。
以下のファイル名は例であり、このリポジトリに存在すると仮定しない。

```bash
python .agents/skills/robot-board-review/scripts/kicad_review.py \
  --schematic schematics/controller.kicad_sch \
  --pcb board/pcb/controller.kicad_pcb
```

`--schematic`と`--pcb`は個別実行/複数指定が可能。`--output-dir`で出力先の親ディレクトリを
指定できる。毎回新しいサブディレクトリへレポート/ログ/`summary.json`を保存する。
終了コードは`0`=指定した自動チェック完了・検出違反なし、`1`=検出違反あり、
`2`=入力/ツール/レポート不備などによる未検証。`0`は製造承認ではない。

- ERC/DRCはエラーだけでなく警告・除外済み違反も出力する。Ignore設定で無効にした
  ルールまでは復活しないため、`.kicad_pro`/`.kicad_dru`と除外理由を別途レビューする。
  シルクのマスク開口/基板端との干渉、文字寸法、未接続、外形、銅箔クリアランス等を
  無効にしない。製造先未定なのに仮の制約を「確認済み」にしない。
- PCBは`--refill-zones`対応CLI（KiCad 10の公式仕様）なら保存せず再充填してDRCする。
  非対応CLI（KiCad 9等）は、レビュー用コピーで全ゾーンを再充填・保存した場合だけ
  `--zones-prefilled`を追加する。この確認なしでは実行を中断する。
  再充填後DRCの成功は、保存済みPCBや既存Gerberの充填状態の保証ではない。
- 回路図とPCBの整合性は別に確認する。本リポジトリは配置先を分けるため、CLIの
  `--schematic-parity`が正しい相手を読むと仮定しない。正しい階層ルートからの
  ネットリスト比較、または明示的に紐付けたレビュー用コピーのGUI整合性チェックを
  行い、相手のファイル/版を記録する。lintはparityを実行しない。
- 実行ログ・JSON・ツール版を確認する。欠落/エラー/非対応CAD/未実行は「未確認」。
  lint自身のユニットテスト成功を、実図面のERC/DRC成功に読み替えない。

自動化するのはKiCadが実際に判定できる範囲のみ。外形にarcが一つあるだけで
「全角Rあり」、文字列があるだけで「ロゴ/リビジョン印刷済み」とは判定しない。
独自の正規表現による図形接触判定を、ネイティブDRCの代替にしない。

## 3. 回路図・PCB・製造出力をレビューする

チェックリストの各IDを`PASS / FAIL / NOT_CHECKED / N/A`に分類し、証拠を付ける。
一部しか見ていない項目は残りを`NOT_CHECKED`とし、N/Aには適用外の理由を書く。
電源安全、ピン対応、部品定格を先に、配置・配線、機構、識別表示、製造出力を続ける。

特に依頼者指定の次の三点を、PCBレビューで省略しない。

- **PCB-06 外形R**: 基板の外周角を丸める。半径・接線接続・鋭角残り・機構との隙間を
  ネイティブ外形/寸法と3Dで確認する。穴/内側切欠きと外周を区別する。
- **PCB-07 シルク**: 表裏の全シルク（文字・線・ロゴ）をパッドのマスク開口と干渉
  させない。DRCと製造用シルク/マスクの重ね合わせで確認する。
- **PCB-08 識別**: ロゴと基板リビジョン番号を実際に印刷されるシルクへ付与する。
  読みやすさと実装後の見え方、図面/BOM/製造データとの版一致まで確認する。

ブログの「1 Aあたり1 mm」を定格判定に使わない。GND分割/等長配線/ビア削減も
一律の規則にせず、実際の電流帰路、信号条件、採用部品の推奨レイアウトから判断する。

## 4. レビュー結果を返す

重大な指摘から列挙し、各指摘に`チェックID / 重要度 / 場所 / 観測事実 /
影響 / 最小の修正案 / 再確認方法 / 根拠`を含める。
場所はファイルに加え、回路図のシート・Ref/ピン/ネット、PCBのRef・座標・層など、
CADで再現できるものにする。行番号だけに依存しない。

重要度の目安は`P1`=安全/損傷/起動不能/製造不能、`P2`=動作・実装・保守上の問題、
`P3`=軽微な改善。外形Rや表示不足も実際の影響から重要度を決める。
推測は断定せず、必要な証拠を挙げる。見た目だけを理由に全面引き直しを求めない。

末尾に、対象コミット/版、実行コマンドと結果、チェックIDの判定表、
未確認事項、承認を妨げる事項をまとめる。指摘がなくても未確認事項は残す。
製造前判定では安全・電源・ピン対応・機構・製造出力の未確認を残して承認しない。
レビューだけの依頼でCADを書き換えたり、設計Issueを閉じたりしない。

## Skill/lintの保守テスト

```bash
python -m unittest discover \
  -s .agents/skills/robot-board-review/tests -v
```

このテストはCLI呼出しと異常系のモック検証であり、KiCad本体や実基板の検証ではない。
